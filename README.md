# Heart Rate Monitor 0.22.0

標準BLE Heart Rate Service対応センサーの心拍を受信し、SQLiteに記録してグラフで確認できるWindowsデスクトップアプリです。VRChat向けOSC送信、CSV出力、日本語・英語UI、Light・Dark・Systemテーマ、タスクトレイ常駐に対応しています。外部アカウントは不要です。

[English](README.en.md)

## 動作環境と起動

Windows 10/11（64ビット）、.NET Framework 4.8、Bluetooth LE対応アダプターが必要です。センサーは標準Heart Rate Service（`0x180D`）とHeart Rate Measurement通知（`0x2A37`）に対応するものを使います。COOSPO HW706などを想定していますが、各機器との互換性は実機確認が必要です。

配布ZIPを展開し、`HeartRateMonitor.exe` を実行します。ソースからビルドした場合は `artifacts/HeartRateMonitor.exe` です。EXEと同梱の `HeartRateMonitor.exe.config` を同じフォルダーに置いてください。

1. WindowsのBluetoothを有効にし、センサーを装着して電源を入れます。
2. 初期設定では起動時に自動検索・接続します。前回成功した検証済み機器を優先し、その次に標準心拍サービスを広告する、またはWindowsに心拍サービスが登録された機器を試します。メーカーや名前による優先はありません。
3. 「ライブ」で心拍数とグラフを確認します。受信値は自動保存します。「履歴」で過去の記録を確認し、表示期間をCSVへ出力できます。
4. 接続バーの「停止」で検索・接続・再接続を停止し、「接続」で再開します。手動選択・再接続・ログコピーは「詳細」にあります。
5. 閉じるボタンは初期設定ではトレイに格納し、記録・OSCを継続します。完全終了はトレイの「終了」です。アイコンのダブルクリックやEXEの再実行で復帰できます。

自動検索が失敗しても、検証済みの機器情報があれば直接接続を試みます。切断後も同じ機器を対象にします。検索の権限拒否や「停止」によるキャンセル時は直接接続に進まず停止し、未検証の保存アドレスは接続候補にしません。

## グラフと履歴

ライブと履歴はグラフを中心に表示し、受信データの表は表示しません。表示期間の最小・平均・最大、平均線、カーソル付近の測定値を確認できます。
縮小表示で測定値を集約する場合は、平均値の折れ線と、その背後に最小〜最大を示す細い縦線を表示します。
履歴グラフ下の時間軸は、時刻と日付（`yyyy/MM/dd`）を2段で表示します。

- 表示幅はボタンまたはスライダーで変更します。最小1分、ライブは最大1時間、履歴は全記録まで。履歴の初期幅は10分です。
- `Ctrl`＋ホイールで拡大・縮小します。履歴のメイングラフでは、ホイール上で過去、下で未来へ、表示幅の10％ずつ移動します。全体グラフはありません。「前の期間」「次の期間」で表示幅ずつ移動し、「最新の記録へ」で最新の期間へ移動できます。
- メイングラフを横にドラッグすると、選択区間の時間・平均・最小・最大・件数を確認できます。
- 月カレンダーで前月・翌月・今月へ移動し、日付を選ぶとその日全体の履歴を表示します。記録のある日は色と「•」で示し、記録のない日も選べます。カレンダーの件数は表示月の有効な心拍だけを集計します。
- 履歴上部は月カレンダーと日時入力を左右に配置し、画面幅に合わせて広がります。日付と開始時刻の下に、入力欄と幅を揃えた移動ボタンを配置しています。
- 「日時から探す」に日付（`yyyy/MM/dd` または `yyyy-MM-dd`）と開始時刻（`HH:mm` または `HH:mm:ss`）を入力し、「指定日時へ移動」またはEnterで直接移動できます。1年以上前も指定でき、現在の表示幅で指定時刻から表示します。PCの現地時刻を使い、夏時間で存在しない時刻はエラー、重複する時刻は早い方を表示します。
- 履歴の「表示期間をCSV出力」は確定した表示期間を、「分析区間をCSV出力」はグラフでドラッグして選択した区間を出力します。分析区間の出力は区間選択中だけ利用でき、Esc・右クリックや表示期間の変更で選択を解除します。保存ダイアログを開いた時点の区間を使います。どちらも開始時刻を含み終了時刻を含まない範囲の元の測定値を、同じ列形式で出力し、0 bpm・接触なしの記録も含めます。`local_time` は現在のローカルタイムゾーンで、OSの暦・表示設定によらない西暦 `yyyy-MM-dd HH:mm:ss.fff` 形式です。

## 設定とOSC

「設定」では、左のカテゴリを選ぶと右側の設定内容が切り替わります。各カテゴリはスクロールせずに操作できます。カテゴリやライブ・履歴を行き来しても未保存の入力を保持し、保存後も選択中のカテゴリに留まります。「一般」（テーマ・言語・トレイ常駐）、「心拍センサー」（自動接続・再接続）、「データ保存」、「OyasumiVR連携」、および「OSC送信」の各項目に分かれています。OSC送信は「送信先とパラメーター」「送信値と無受信時の動作」「送信状況とテスト」に整理しています。設定を編集し、「保存して適用」で反映します。上部の太陽・月アイコンによるテーマ変更は即座に保存します。

OSCは初期設定で有効、送信先はUDP `127.0.0.1:9000` です。VRChat側でOSCを有効にし、アバターに対応するパラメーターを用意します。

- Int32：`/avatar/parameters/VRCOSC/Heartrate/Value`。心拍数を0〜255に制限します。
- Float32：`/avatar/parameters/HRPercent`。初期設定は0〜200 bpmを0.0〜1.0へ変換します。式は `clamp((bpm - 最小) / (最大 - 最小), 0, 1)` です。

IP・ポート・パラメーター名・換算範囲は変更できます。送信状態と単発テストは設定画面にあります。テストは保存済み設定で2値を一度だけ送信し、測定記録は作りません。UDP送信成功はVRChatでの受信・適用を保証しません。0 bpm・明示的な接触なしは保存しますが送信しません。

### 切断・無受信時のOSC動作

設定のOSC欄で次の2モードを選択し、「保存して適用」で反映します。

- **最終値を維持**：無受信時は送信せず、受信側の最後の値を変更しません。
- **無受信時に代替値を送信**（初期値）：指定時間（1〜3600秒、初期値5秒）通知が届かなければ、設定したInt・Float代替値を一度送信します。Intは0〜255、Floatは0.0〜1.0で個別に指定でき、初期値は両方0です。代替値にはbpmの制限・Floatの心拍換算を適用せず、入力した値をそのまま送信します。起動からまだ通知がない場合や、手動停止中も対象です。0 bpm・接触なしを含む各通知の受信で待ち時間を数え直します。送信状況には無受信による代替値送信と表示し、測定記録には追加しません。正常な測定が再開すると通常送信に戻ります。

この項目がない旧設定にも初期値を適用します。すでに保存したモード・秒数は維持し、代替値のない旧設定では従来どおり両方0を送信します。

OSC無効時とアプリ終了後は代替値を送信しません。無受信時間はPCの時計変更の影響を受けない経過時間で判定します。設定変更時点ですでに時間を超えていれば、適用後に代替値を送信します。無受信中に代替値を変更して保存すると、新しい値を一度送信します。同じ設定の再保存では再送しません。単発テストは受信扱いにせず、無受信時はテスト値も代替値に置き換わります。UDP送信成功は受信側での適用を保証しません。

## データ保存とバックアップ

通常の保存先は `%LOCALAPPDATA%\HeartRateMonitor\` です。`heartrate.db` が測定記録、`settings.json` が設定、`connection.log` が診断ログです。

接続・記録・OSC送信のエラーと、起動時の設定読み込み・保持期限削除の失敗を記録します。記録・OSCエラーは画面更新を待たずにログへ渡します。ログを保存できない場合は、実行中の「ログコピー」に通知と保存失敗を保持します。メモリ上のログは終了すると失われるため、必要なログは終了前にコピーしてください。

保存期間の初期値は**無期限**です。1・7・30・90・365日にも変更できます。有限の期間では既存の記録も対象に、起動時・方針変更後・動作中の1分ごとの確認で古い記録を自動削除します。**削除後は復元・CSV出力できません。無期限に戻しても復元されません。** 必要な記録は変更前に書き出してください。保存期間が未設定の旧設定も無期限として扱います。

### OyasumiVRの自動睡眠ラベル

同じPCでOyasumiVRを起動し、OyasumiVR側でOSCサーバーを有効にしてください。本アプリの「設定 → OyasumiVR連携」にあるOyasumiVR連携は初期状態で有効です。OSCQueryポートの初期値`0`はOyasumiVRプロセスのローカル待受ポートを自動検出します。自動検出できない場合は、OyasumiVRに表示される**OSCQuery（HTTP）ポート**を指定して保存してください（OSCのUDPポートとは異なります）。接続先は常に`127.0.0.1`です。VRChatの起動やOSC転送先の変更は不要です。

2秒ごとにOyasumiVRの睡眠モードを読み取り、有効な間を履歴グラフに「睡眠 · OyasumiVR」と表示します。[公式の睡眠モード公開アドレス](https://github.com/Raphiiko/OyasumiVR/blob/develop/src-ui/app/services/osc-control/methods/sleep-mode.osc-method.ts) `/OyasumiVR/SleepMode` をOSCQueryで読み取るだけで、OyasumiVRの状態は変更しません。ラベルは睡眠モードの状態を示し、心拍から睡眠を判定する機能ではありません。

区間は最初に有効と確認した時点から記録し、無効を確認した時点で終了します。通信エラー・取得不能時は最後に確認できた時点までを残し、未確認の時間を睡眠として補いません。PCのスリープなどで確認間隔が10秒を超えた場合や、本アプリの再起動、連携先の変更、連携の無効化でも区間を分けます。復旧後は自動で再確認します。設定と履歴に連携状態を表示し、エラーはログにも残します。

心拍記録のない時間帯も、睡眠ラベルを履歴で選択・表示できます。心拍測定値や統計、CSVの列形式は変更しません。睡眠ラベルはCSVに含みません。手動のメモ・区間ラベルの追加・編集・検索は削除しました。以前の手動メモがDBにある場合も睡眠に変換・表示せず、既存テーブルはそのまま残します。

サイドバーの「睡眠」では、7日間・30日間・指定期間（最大366日）の睡眠時平均心拍数、平均睡眠時間、普段の睡眠時間帯を確認できます。概要・睡眠リズム・選択区間の心拍グラフは、ページ全体をスクロールせずに一画面で確認できます。日別の横棒グラフは7日ずつ矢印で切り替え、平均は選んだ集計期間全体を対象にします。記録できた区間だけを表示し、通信断の空白を睡眠として補いません。日付は一日の区切りがある側の日付です。初期値は正午〜翌正午で、「設定 → OyasumiVR連携 → 睡眠の一日の区切り」で変更できます。

平均睡眠時間は、一日ごとの記録時間の合計を記録のある日数で割ります。期間の境界をまたぐ区間は集計期間内だけを数え、重複区間は二重に数えません。記録のない日は0時間にせず、記録中・集計から除外した区間も平均の対象外です。睡眠時平均心拍数は対象区間内の有効な実測値の平均で、測定間隔による重み付けは行いません。心拍データがない場合は「—」を表示し、睡眠・心拍それぞれの集計対象日数も表示します。普段の睡眠時間帯は、一日で最も長い連続記録の開始・終了時刻の中央値です。通信断で分割された記録や昼寝がある場合は、横棒グラフと併せて確認してください。

上の睡眠リズムで区間をクリックすると、下のグラフにその区間の心拍数を表示します。Tabで睡眠リズムにフォーカスし、矢印キー・Home・Endでも区間を選択できます。選択区間の開始・終了と平均心拍数を表示し、心拍データがなければ空のグラフと「心拍データなし」を表示します。睡眠記録の一覧、手動削除、集計からの除外・再追加操作はありません。既存の除外状態は保持します。

有限の保存期間では、終了日時が削除期限以前の睡眠ラベルも完全に削除します。期限をまたぐ区間は元の日時のまま残します。**削除は元に戻せません。**

バックアップはトレイから終了した後、保存先フォルダー全体をコピーしてください。睡眠ラベルも同じデータベースに保存されます。CSVは測定値の出力用で、復元用ではありません。無期限では使用容量が増えるため、空き容量を確認してください。

終了時は、受信済みデータの保存と進行中のCSV出力の完了を待ちます。出力中のファイルが大きい場合、終了に時間がかかることがあります。

## 開発と検証

WPF / .NET Framework 4.8、Windows WinRT BLE API、OS付属の `winsqlite3.dll` を使用します。.NET SDK（Roslyn）とWindows SDKメタデータが必要です。NuGetは使用しません。

コンパイラーは、PATH上の `dotnet` がリポジトリ内で選択するSDKから取得します。SDKの配置先を固定せず、preview版の名前や `global.json` による選択も.NET CLIに従います。

Windows SDKメタデータは、インストール済みのバージョンを数値で比較して最新のUnionMetadataを選びます。Facade用メタデータは除外し、旧SDKのルート直下の配置にも対応します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
```

開発ビルドは `artifacts/HeartRateMonitor.exe` を上書きし、設定ファイル・日英README・配布ZIPも `artifacts/` 直下に配置します。ZIPにはEXE・設定ファイル・日英READMEを含みます。実行中のEXEを置き換える前に、トレイからアプリを終了してください。

`artifacts/` 直下には現在の開発ビルド成果物を置きます。ログと検証資料は `artifacts/logs/`、リポジトリ保守用バックアップは `artifacts/backups/` に保存します。ビルドや検証ではバージョンを確定せず、バージョン別フォルダーも自動作成しません。`artifacts/versions/version-X.Y.Z/` は明示的に指示されたバージョン確定時のスナップショット用、既存の `artifacts/versions/version-0.0.0/` はバージョン不明の旧生成物用です。

UI変更時は対話可能なWindowsデスクトップで次の検証も行います。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\ui-smoke.ps1
.\artifacts\HeartRateMonitor.exe --data-dir .\artifacts\logs\verification\render --smoke-test
```

UIスクリプトは `ISOLATED UI TEST` と明示した一時データを使います。描画スモークテストは日本語・英語とLight・Dark・Systemの画面を確認し、PNGと `smoke-checks.txt` を出力します。テスト用の設定も保存するため、`--data-dir` には必ず通常の保存先とは別の専用ディレクトリを指定してください。スモークテストは保存先の省略や通常保存先の指定を拒否します。値がない `--data-dir`、その重複指定、不明な引数も起動エラーになります。

依存パッケージを使わない実行入口 `tests/Tests.cs` から、分野別の `tests/Tests.*.cs` を呼び出します。`build.ps1 -Test` はこれらをまとめてコンパイル・実行し、実機診断用の `BluetoothDiagnostic.cs` は別に扱います。

`build.ps1 -Test` は、隔離したSDK一覧で探索と失敗処理を確認する `tests/build-sdk.ps1` と、Windows SDKの選択を確認する `tests/build-metadata.ps1` も実行します。`-Diagnostic` を併用した場合は、実機診断が異常終了するとビルドも失敗として停止します。

Bluetooth診断は機器一覧と心拍サービスの両方を列挙し、一方の列挙が失敗しても他方を試します。列挙エラーやキャンセルがあれば終了コード1を返します。正常に列挙できて結果が0件の場合は失敗としません。列挙結果の成功・失敗処理は、実機を使わない回帰テストでも確認します。

自動テストは通知解析、接続制御、OSC、SQLite・CSV、保持期限、履歴・分析などを確認します。実機での動作確認は別です。HW706の実通知・切断復帰・長時間稼働・VRChatへの適用は、実機を使った検証が必要です。

Beko.BluetoothHeartRateOSCは動作上の参考とし、実装は独立して作成しています。
