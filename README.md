# Heart Rate Monitor 0.23.0

標準BLE Heart Rate Service対応センサーから心拍数を受信し、ローカルのSQLiteデータベースに記録してリアルタイムおよび過去の推移をグラフ表示するWindowsデスクトップアプリケーションです。VRChat向けOSC送信、CSVエクスポート、OyasumiVRと連携した睡眠モードの自動記録と分析、日本語・英語UI切替、Light・Dark・Systemテーマ対応、タスクトレイ常駐に対応しています。外部アカウントやクラウドサービスへの登録は不要です。

## 動作環境とクイックスタート

### 必要環境

- **OS**: Windows 10 / 11（64ビット版）
- **ランタイム**: .NET Framework 4.8
- **Bluetooth**: Bluetooth LE（Low Energy）対応アダプター
- **心拍センサー**: 標準BLE Heart Rate Service（サービスUUID `0x180D`）および Heart Rate Measurement 通知（キャラクタリスティックUUID `0x2A37`）に対応したセンサー機器（COOSPO HW706などを想定）。各機器との接続互換性は実機での確認が必要です。

### 初回起動と基本手順

配布ZIPを展開し、`HeartRateMonitor.exe` を実行します。ソースからビルドした場合は `artifacts/HeartRateMonitor.exe` です。EXEと同梱の `HeartRateMonitor.exe.config` を同じフォルダーに置いてください。

1. **センサーの準備**: WindowsのBluetoothを有効にし、心拍センサーを装着して電源を入れます。
2. **自動接続**: 初期設定では起動時に自動検索・接続します。前回成功した検証済み機器を優先し（広告が見つからない場合でも直接接続を試行）、その次に標準心拍サービスを広告する機器やWindowsに心拍サービスが登録された機器を試します。メーカーや機種名による優先はなく、名前だけで未検証機器を接続候補にすることはありません。
3. **心拍の確認と記録**: 「ライブ」で心拍数とグラフを確認します。受信値はローカルSQLiteに自動保存されます。「履歴」で過去の記録を確認し、表示期間をCSVへ出力できます。
4. **接続の停止と再開**: 接続バーの「停止」で検索・接続・自動再接続を停止し、「接続」で再開します。手動選択・再スキャン（Scan）・再接続・ログコピーは「詳細」画面にあります。
5. **トレイ常駐と完全終了**: 閉じるボタンは初期設定ではトレイに格納し、記録・OSC送信を継続します。アイコンのダブルクリック、「ウィンドウを開く」、またはEXEの再実行で復帰できます。完全終了はトレイの「終了」です。記録キューをフラッシュして終了します。

> **言語の切り替え**: 初期UI表示は日本語です。「設定 → 一般 → 表示言語」で「English」を選択し、「保存して適用」を押すことで切り替えられます。

### センサー接続と再試行の仕様

- **検証済み機器への直接接続**: 自動検索で広告が見つからない場合でも、過去に成功した検証済みの機器情報があれば直接接続を試みます。切断後も同じ機器を対象にします。
- **停止・権限拒否時の安全停止**: 検索の権限拒否や「停止」によるキャンセル時は直接接続に進まず停止します。未検証の保存アドレスを接続候補にすることはありません。
- **無受信判定と切断**: 通知が届かない状態が5秒続くとライブ画面の心拍数がクリア（「—」）されます。通知が20秒間途絶えると接続が切断され、自動再接続が有効であれば再試行サイクルを開始します。広告スキャンは約8秒間実施され、再試行の間隔は5秒です。権限が拒否された場合は自動再試行を停止します。

## グラフ表示・履歴とCSV出力

### ライブ表示

- **グラフ中心のUI**: 測定値の生データ一覧表は配置せず、グラフ表示に特化しています。カーソルを合わせて付近の測定値や集約バケットを確認できます。
- **表示幅の選択**: プリセットボタン（10分・30分・1時間）またはスライダー（最小1分〜最大1時間）で表示幅を変更できます。
- **リアルタイム更新**: 最新時刻が常に右端に保たれます。`Ctrl`＋ホイールで拡大・縮小できます。
- **統計値**: 表示期間の有効な測定値（0 bpmおよび明示的な非装着・接触なしを除く）から、最小・平均（破線表示）・最大を表示します。
- **データ保持範囲**: ライブグラフは現在の起動中にメモリ内に保持されたデータ（最大1時間分）を表示対象とし、過去のデータベース記録は再読み込みしません。

### 履歴の閲覧と操作

- **表示期間の幅**: ボタンまたはスライダーで最小1分から全記録（All）まで選択できます。起動時の初期表示幅は10分です。
- **時間軸の表示**: 履歴グラフ下の時間軸は、時刻と日付（`yyyy/MM/dd`）を2段で表示します。
- **集約表示（ヒゲ表示）**: 縮小表示で測定値が集約される場合は、平均値の折れ線グラフの背後に最小〜最大を示す細い縦線（ヒゲ）を表示します。カーソルを合わせて付近のサンプルやバケットを確認できます。
- **マウスホイール移動**: メイングラフ上でホイールを上回転すると過去へ、下回転すると未来へ、表示幅の10%ずつ移動します（全体グラフは廃止されており、ページ全体の縦スクロールは発生しません）。`Ctrl`＋ホイールでカーソル位置を中心に拡大・縮小できます。
- **期間ナビゲーション**: 「前の期間」「次の期間」で表示幅ずつ移動できます。「最新の記録へ」を押すと最新データを再読み込みして最新の期間へ移動します。

### 日時指定移動と月カレンダー

- **レイアウト配置**: 履歴上部は月カレンダーと日時入力を左右に配置し、画面幅に合わせて広がります。日付と開始時刻の下に、両入力欄と幅を揃えた移動ボタンを配置しています。
- **月カレンダー**: 前月・翌月・今月へ移動できます。記録のある日はアクセント色と「•」で示し、カーソルを合わせると有効件数を確認できます。記録のない日を含む任意の日付を選ぶと、現地時刻の午前0時から翌日の午前0時までの履歴を表示します。夏時間の切り替え日は24時間とは限りません。Tabキーでカレンダーにフォーカスし、矢印キーとEnterで選択可能です。カレンダーの件数は表示月の有効な心拍だけを集計します。
- **日時から探す**: 日付（`yyyy/MM/dd` または `yyyy-MM-dd`）と開始時刻（`HH:mm` または `HH:mm:ss`）を入力し、「指定日時へ移動」またはEnterで直接移動できます。1年以上前も指定でき、現在の表示幅で指定時刻から表示します。PCの現地時刻（ローカルタイムゾーン）を使い、夏時間で存在しない時刻はエラーを表示し、重複する時刻は早い方を表示します。

### 分析区間の選択

- メイングラフ上を横にドラッグすると、選択区間の時間・平均・最小・最大・件数を確認できます。
- 開始時刻を含み終了時刻を含まない半開区間 `[from, to)` の元の有効測定値（0 bpm・接触なしを除く）が集計に使用されます。
- `Esc`、クリック、右クリック、または表示期間の変更で選択を解除します。

### CSVエクスポート仕様

履歴画面から以下の2種類のエクスポートを実行できます。いずれも同一の列構成と元の生データをタイムスタンプ順に出力します。

1. **表示期間をCSV出力**: 確定した表示期間を出力します。
2. **分析区間をCSV出力**: グラフでドラッグして選択した区間を出力します（区間選択中だけ利用でき、保存ダイアログを開いた時点の区間を使用します）。

- **出力仕様**:
  - **エンコーディング**: BOM付きUTF-8。
  - **対象データ**: どちらも開始時刻を含み終了時刻を含まない範囲 `[from, to)` の元の測定値を出力し、0 bpmや接触なしの記録も含めます。
  - **列構成**:
    ```csv
    utc_time,local_time,bpm,contact,rr_ms,energy_kj,device,session
    ```
  - `utc_time`: ISO 8601表記（例: `2026-10-31T05:30:00.0000000+00:00`）。
  - `local_time`: 現在のローカルタイムゾーンで、OSの暦・表示設定によらない西暦 `yyyy-MM-dd HH:mm:ss.fff` 形式。
  - `bpm`: 心拍数（整数値）。
  - `contact`: 接触状態（`1`=接触あり、`0`=接触なし、未検出・不明時は空文字）。
  - `rr_ms`: RR間隔（ミリ秒）。
  - `energy_kj`: 消費エネルギー（kJ）。
  - `device`: 機器識別文字列。
  - `session`: 接続セッション識別子。
- **保護機構**: データベースファイル（`heartrate.db`, `-wal`, `-shm`, `-journal` 等）と同じ場所への出力は拒否されます。一時ファイルを用いたアトミック書き込みにより最終出力先への不完全な上書きを防止します（一時ファイルのクリーンアップ自体が失敗するケースはあるため、一時ファイルが一切残らないことを保証するものではありません）。CSVインポート機能はありません。

## 設定とOSC送信

### 設定画面の構成

設定画面は左のカテゴリーを選ぶと右側の設定内容が切り替わります。各カテゴリーはスクロールせずに操作できます。カテゴリーやライブ・履歴を行き来しても未保存の入力を保持し、「保存して適用」後も選択中のカテゴリーに留まります。

1. **一般**: テーマ（Light / Dark / System）、表示言語（日本語 / English）、閉じるボタンでタスクトレイに格納。※上部の太陽・月アイコンによるテーマ変更は即座に保存されます。Windowsの設定に再び追従させるには設定画面で「System」を選択します。
2. **心拍センサー**: 起動時の自動接続、切断時の自動再接続。
3. **データ保存**: データの保持期間（無期限、1日、7日、30日、90日、365日）。
4. **OyasumiVR連携**: OyasumiVR連携の有効化、OSCQueryポート、睡眠の一日の開始時刻（0〜23時）。
5. **送信先とパラメーター**: 送信先IPアドレス、ポート番号、Intパラメーター名、Floatパラメーター名。
6. **送信値と無受信時の動作**: Float換算範囲（最小bpm・最大bpm）、切断・無受信時の動作モード、タイムアウト時間、代替値（Int・Float）。
7. **送信状況とテスト**: 送信ステータス、直近の送信値、単発OSC送信テスト。

### VRChat向けOSC送信設定

OSCは初期設定で有効、送信先はUDP `127.0.0.1:9000` です。VRChat側でOSCを有効にし、アバターに対応するパラメーターを用意します。

- **送信先アドレスとポート**: 送信先にはIPアドレス（IPv4またはIPv6）を指定します（ホスト名は不可）。ポートは 1〜65535 です。
- **Int32パラメーター**:
  - 初期名: `/avatar/parameters/VRCOSC/Heartrate/Value`
  - 送信値: 心拍数を0〜255に制限して送信します。
- **Float32パラメーター**:
  - 初期名: `/avatar/parameters/HRPercent`
  - 送信値: 設定範囲を0.0〜1.0へ線形変換して送信します。
  - 式: `clamp((bpm - 最小) / (最大 - 最小), 0.0, 1.0)`
  - 初期設定: 0〜200 bpm（範囲: `0 <= 最小 < 最大 <= 65535`）。
- **パラメーター名の指定規則**:
  - パラメーター名は `/avatar/parameters/` 配下のASCII文字（空白・ワイルドカード `#*,?[]{}` および `//` 不可）である必要があります。
  - 先頭スラッシュがない名前には自動的に `/avatar/parameters/` が補完されます。
  - IntとFloatには重複しない別々の名前を指定してください。

> [!NOTE]
> 0 bpm や明示的な接触なし（非装着）の記録はデータベースに保存されますが、OSC送信は行われません。

### 単発送信テスト

設定画面の「送信状況とテスト」で、指定した心拍数（初期値80、範囲1〜65535）を一度だけ送信するテストを行えます。

- **前提条件**: OSCが**有効化され、保存済みであること**が必要です。
- 保存済み設定で2値を一度だけ送信します。
- **測定記録の非汚染**: テスト送信は測定記録を作らず、受信値としても扱いません（無受信タイマーをリセットしません）。正常な測定が再開すると通常送信に戻ります。
- **UDP送信の性質**: UDP送信成功はOSがパケットを受け付けたことを示すのみであり、VRChatでの受信や適用を保証しません。VRChatのOSCデバッグ表示で確認してください。

### 切断・無受信時のOSC動作（タイムアウト）

設定のOSC欄で次の2モードを選択し、「保存して適用」で反映します。

1. **最終値を維持（Keep last value）**:
   - 無受信時は送信せず、受信側の最後の値を変更しません。
2. **無受信時に代替値を送信（Send fallback values on timeout）**（初期値）:
   - 指定時間（1〜3600秒、初期値5秒）通知が届かなければ、設定したInt（0〜255、初期値0）・Float（0.0〜1.0、初期値0.0）代替値を一度送信します。
   - **換算の非適用**: 代替値にはbpmの制限やFloatの心拍換算を適用せず、入力した値をそのまま送信します。
   - 起動からまだ通知がない場合や、手動停止中も対象です。0 bpm・接触なしを含む各通知の受信で待ち時間を再計測します。
   - 判定にはPCの時計変更の影響を受けない単調増加経過時間を使用します。
   - 送信状況には「無受信のため代替値をUDP送信済み」と表示し、測定記録には追加しません。正常な測定が再開すると通常送信に戻ります。
   - OSC無効時とアプリ終了後は代替値を送信しません。

- **旧設定の移行と適用タイミング**:
  - この項目がない旧設定にも初期値（代替値送信・5秒）を適用します。すでに保存したモード・秒数は維持し、代替値のない旧設定では従来どおり両方0を送信します。
  - 設定変更時点ですでに時間を超えていれば、適用後に代替値を送信します。
  - 無受信中に代替値を変更して保存すると、新しい値を一度送信します。同じ設定の再保存では再送しません。
  - 単発テストは受信扱いにせずタイマーをリセットしないため、無受信時はテスト値もタイムアウト代替値に置き換わります。

## データ保存と保持ポリシー

### 保存ファイル構成

通常の保存先は `%LOCALAPPDATA%\HeartRateMonitor\` です。

- **`heartrate.db`**: SQLiteデータベース本体。測定記録テーブル（`readings`）、睡眠ラベルテーブル（`sleep_intervals`）、および管理テーブル（`sleep_management`）が保存されます。WALモードおよび `FULL` 同期を使用します。
- **`settings.json`**: アプリケーション設定および前回接続した検証済み機器情報。
- **`settings.json.bak`**: 設定変更時に自動保存される直前の設定ファイル。
- **`connection.log`**: 現在のセッションの診断ログ（最大250行、UTF-8 BOM付き）。

### 設定読み込み失敗時のフェイルセーフと復旧

設定の読み込みに失敗した場合は警告を表示し、安全のため**OSCを無効にして起動**します。

- ユーザーが「保存して適用」を成功させるまでは、センサー接続による設定の自動保存を停止し、ディスク上の元の `settings.json` と `settings.json.bak` を保持します。
- この間のツールバーでのテーマ変更はメモリ上にだけ反映します。
- 復旧時の最初の明示的な保存でも既存のバックアップを保持し、その後は通常の自動保存に戻ります。
- **バックアップからの手動復旧手順**: アプリを終了し、両ファイルを別の場所に退避した上で、正常な `settings.json.bak` を `settings.json` にコピー（バックアップを移動・削除せず複製）してから再起動してください。

### データ保持期間（自動削除）の仕様と警告

設定の「データ保存」で保持期間を設定できます。

- **選択肢**: **無期限（Unlimited）**（初期値）、**1日**、**7日**、**30日**、**90日**、**365日**。保存期間が未設定の旧設定も無期限として扱います。
- **自動削除のタイミング**: 有限の期間では**既存の記録も対象**に、起動時、方針変更後、および動作中の毎分1回の確認で、現在時刻から指定日数（24時間×日数）を超過した古い記録を自動削除します。
- **睡眠ラベルの削除条件**: 終了日時が削除期限以前の睡眠ラベルを完全に削除します。期限をまたぐ区間は元の日時のまま残します。
- **有効ポリシーの表示**: 現在有効な保持期間は「ライブ」および「履歴」に表示されます。

> [!WARNING]
> **不可逆なデータ削除に関する重要な警告**:
> 有限の保持期間により削除された記録は**復元・CSV出力できません。無期限に戻しても復元されません。** 必要な記録は保持期間を変更する前にCSVへ書き出してください。無期限では使用容量が増えるため空き容量を確認してください。なお、データ削除を行ってもデータベースファイルサイズが直ちに縮小するとは限りません。

### 診断ログとバックアップ手順

- **診断ログ**: 接続・記録・OSC送信のエラーと、起動時の設定読み込み・保持期限削除の失敗を即座に記録します。記録・OSCエラーは画面更新を待たずにログへ渡します。ログをファイルに保存できない場合は、メモリ上のログに通知と保存失敗を保持し、「詳細」画面の「ログコピー」から取得できます（メモリ上のログはアプリ終了時に失われます）。
- **バックアップ手順**: トレイからアプリを終了した後、保存先フォルダー全体（`%LOCALAPPDATA%\HeartRateMonitor\`）をコピーしてください。睡眠ラベルも同じデータベースに保存されます。CSVは測定値の出力用であり、復元用ではありません。
- **復元手順**: アプリを終了し、現在のフォルダーを別途退避した上でバックアップで置き換えて再起動してください（復元後も起動時に設定された保持ポリシーが適用されます。内蔵のバックアップ/復元UIはありません）。
- **終了時の保護**: 終了時は、受信済みデータの保存と進行中のCSV出力の完了を待ちます。出力中のファイルが大きい場合、終了に時間がかかることがあります。なお、クラッシュや突然の電源断ではキュー内の測定値が失われる場合があります。

## OyasumiVR睡眠連携と分析

### 連携の概要と設定

同じPCで [OyasumiVR](https://github.com/Raphiiko/OyasumiVR) を起動し、OyasumiVR側でOSCサーバーを有効にしてください。本アプリの「設定 → OyasumiVR連携」にあるOyasumiVR連携は初期状態で有効です。

- **ポート設定**: OSCQueryポートの初期値 `0` はOyasumiVRプロセスのローカル待受ポートを自動検出します。自動検出できない場合は、OyasumiVRに表示される **OSCQuery（HTTP）ポート** を指定して保存してください（OSCのUDPポートとは異なります）。接続先は常に `127.0.0.1` です。VRChatの起動やOSC転送先の変更は不要です。
- **状態の取得**: 2秒ごとに [公式の睡眠モード公開アドレス](https://github.com/Raphiiko/OyasumiVR/blob/develop/src-ui/app/services/osc-control/methods/sleep-mode.osc-method.ts) `/OyasumiVR/SleepMode` をOSCQueryで読み取り、有効な間を履歴グラフに「睡眠 · OyasumiVR」と表示します。OyasumiVRの状態は変更しません。ラベルは睡眠モードの状態を示し、心拍から睡眠を判定する機能ではありません。

### 睡眠モードの記録判定と通信断の扱い

- **区間の開始と終了**: 最初に有効と確認した時点から記録し、無効を確認した時点で終了します。
- **未確認時間の非補完**: 通信エラー・取得不能時は最後に確認できた時点までを残し、**未確認の時間を睡眠として補いません**。
- **区間の分割**: PCのスリープなどで確認間隔が10秒を超えた場合や、本アプリの再起動、連携先の変更、連携の無効化でも区間を分けます。復旧後は自動で再確認を再開します。設定と履歴に連携状態を表示し、エラーはログにも残します。
- **心拍記録との関係**: 心拍記録のない時間帯も睡眠ラベルを履歴で選択・表示できます。心拍測定値や統計、CSVの列形式は変更しません。睡眠ラベルはCSVに含みません。手動のメモ・区間ラベルの追加・編集・検索は削除されました。以前の手動メモがDBにある場合も睡眠に変換・表示せず、既存テーブルはそのまま残します。

### 睡眠ダッシュボードと分析統計

サイドバーの「睡眠」では、7日間・30日間・指定期間（最大366日）の睡眠時平均心拍数、平均睡眠時間、普段の睡眠時間帯を確認できます。概要・睡眠リズム・選択区間の心拍グラフは、ページ全体をスクロールせずに一画面で確認できます。

- **睡眠の一日の開始時刻**:
  - 日付は一日の開始時刻がある側の日付です。初期値は0時〜翌0時で、「設定 → OyasumiVR連携 → 睡眠の一日の開始時刻」から **0〜23時の任意の時刻** に変更・保存できます。以前に保存した開始時刻は保持されます。
  - 日付をまたぐ横軸では0時を強調した縦線で示し、睡眠リズムには翌日の表示、下の心拍グラフには切り替わる日付を添えます。
- **分析指標の計算仕様**:
  - **平均睡眠時間**: 一日ごとの記録時間の合計を**記録のある日数**で割ります（期間の境界をまたぐ区間は集計期間内だけを数え、重複区間は二重に数えません。記録のない日は0時間にせず、記録中・集計から除外した区間も平均の対象外です）。
  - **睡眠時平均心拍数**: 対象区間内の有効な実測値の算術平均で、測定間隔による重み付けは行いません。心拍データがない場合は「—」を表示し、睡眠・心拍それぞれの集計対象日数も表示します。
  - **普段の睡眠時間帯**: 一日で最も長い連続記録の開始・終了時刻の中央値です。通信断で分割された記録や昼寝がある場合は、横棒グラフと併せて確認してください。

### 睡眠リズムと記録一覧（ラベル削除）

上部の「リズム／記録一覧」で表示を切り替えられます。

- **睡眠リズム**: 日別の横棒グラフは7日ずつ矢印で切り替えられます。概要の平均指標は選んだ集計期間全体を対象にします。記録できた区間だけを表示し、通信断の空白を睡眠として補いません。
- **記録一覧**: 選んだ集計期間の睡眠ラベルを新しい順に表示し、開始・終了日時、記録時間、記録中・集計対象外などの状態を確認できます。
- **区間心拍グラフの連動**: リズムの区間または一覧の行を選ぶと、下のグラフにその区間の心拍数を表示します（Tabキーでフォーカスし、矢印キー・Home・Endでも選択可能）。選択区間の開始・終了と平均心拍数を表示し、心拍データがなければ空のグラフと「心拍データなし」を表示します。
- **睡眠ラベルの削除**:
  - 記録一覧で対象を選び「ラベルを削除…」を押すと、削除する区間の日時を確認できます。「キャンセル」または `Esc` で取り消せます。
  - **不可逆な削除と心拍データの保持**: **ラベルの削除は元に戻せませんが、元の心拍記録は残ります。** 削除後は睡眠の集計・リズム・履歴のラベル表示も更新します。
  - 記録中のラベルは削除できません。集計からの除外・再追加操作はなく、既存の除外状態は保持します。
  - 有限の保存期間では、終了日時が削除期限以前の睡眠ラベルも完全に削除します。期限をまたぐ区間は元の日時のまま残します。**削除は元に戻せません。**

## トラブルシューティングと制限事項

### センサーが見つからない・接続できない

- センサーの電源、バッテリー、機器の取扱説明に応じた装着・密着状態、および距離を確認してください（光学式・電極式それぞれの装着方法に従ってください）。
- WindowsのBluetoothが有効になっているか確認してください。
- センサーが他のアプリやスマートフォン等と接続中（占有状態）でないか確認してください。
- 自動検出されない場合は接続バーの「詳細」を開き、「スキャン」を実行して一覧から機器を手動選択して「接続」を試みてください。
- 「接続済み・受信待ち」は、接続は成立しているものの心拍通知がまだ届いていない状態です。「心拍受信中」と区別してください。ログが必要な場合は終了前に「ログコピー」を行ってください。

### OSCがVRChatに反映されない

- 保存済みの送信先IP・ポート、パラメーター名・型、VRChat側のOSC有効設定、およびVRChatのOSCデバッグ表示を確認してください。
- UDP送信成功はOSがパケットを受け付けたことを示すのみであり、アバターへの適用を保証するものではありません。

### データ保存や設定復旧のエラー

- 保存先フォルダーの空き容量とアクセス権限を確認してください。
- 設定読み込みに失敗した場合は警告が表示され、OSCが無効化されます。設定内容を修正して「保存して適用」を行ってください。

### 既知の制限事項

- **トレイメニューの配色**: WPFウィンドウはLight / Dark / Systemテーマに対応していますが、標準WinFormsトレイメニューはOS標準スタイルとなりアプリの動的パレットに明示的には追従しません。
- **実機検証の範囲**: センサーとの相性、スリープ復帰、長時間稼働、およびVRChatへの適用は実機ハードウェアを使った検証が必要です。自動テストはそれらの結果を代替するものではありません。

## 開発・ビルドと検証

### 技術スタックとビルド要件

- **プラットフォーム**: x64 Windows 10 / 11、.NET Framework 4.8
- **UI / 通信 / DB**: WPF、Windows WinRT BLE API、OS付属 `winsqlite3.dll`（全パラメーターバインド、WALモード）。NuGetパッケージは使用しません。
- **ツール要件**: .NET SDK（Roslyn）およびWindows SDKメタデータが必要です。
- **コンパイラー解決**: PATH上の `dotnet` がリポジトリ内で選択するSDK（`tools/resolve-build-sdk.ps1`）から取得します。SDKの配置先を固定せず、preview版の名前や `global.json` による選択も.NET CLIに従います。
- **Windows SDK解決**: `tools/resolve-windows-metadata.ps1` がインストール済みのバージョンを数値比較して最新のUnionMetadataを選びます。Facade用メタデータは除外し、旧SDKのルート直下配置にも対応します。

### ビルド手順と成果物

ビルドはリポジトリのルートから実行します。通常ビルド時は必ず `-Test` を付与してください。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
```

- **成果物の配置**:
  - 開発ビルドは常に `artifacts/` 直下に出力され、前回の開発ビルドを上書きします。
  - `artifacts/HeartRateMonitor.exe`
  - `artifacts/HeartRateMonitor.exe.config`
  - `artifacts/README.md` および `artifacts/README.en.md`
  - `artifacts/HeartRateMonitor-win-x64.zip`（EXE、構成ファイル、日英READMEを同梱）
- **ビルド時の注意**: 実行中のEXEを置き換える前に、トレイからアプリを終了してください。
- **フォルダー規則とバージョン方針**:
  - 開発出力は直接 `artifacts/` 直下に配置し、`artifacts/dev-*` 等は作成しません。
  - ログと検証資料は `artifacts/logs/`、リポジトリ保守用バックアップは `artifacts/backups/` に保存します。
  - ビルドや検証によって製品バージョンを確定・引き上げることはなく、バージョン別フォルダーも自動作成しません。
  - `artifacts/versions/version-X.Y.Z/` は明示的に指示されたバージョン確定スナップショット用、既存の `artifacts/versions/version-0.0.0/` はバージョン不明の旧生成物用です。現在の製品バージョンは `0.23.0` です。

### 自動テストとUIスモークテスト

依存パッケージを使わない実行入口 `tests/Tests.cs` から分野別の `tests/Tests.*.cs` を呼び出します。

- **自動テストの検証内容**: 通知解析、接続制御、OSCとテスト隔離、設定、SQLite・CSV、保持期限、履歴・分析等を確認します。
- **スクリプトによるテスト**:
  - `build.ps1 -Test` は、隔離したSDK一覧で探索と失敗処理を確認する `tests/build-sdk.ps1` と、Windows SDKの選択を確認する `tests/build-metadata.ps1` も実行します。
- **ハードウェアBluetooth診断**:
  - `-Diagnostic` を併用した場合、実機診断 `BluetoothDiagnostic.exe` をビルド・実行します。
  - 機器一覧と心拍サービスの両方を列挙し、一方の列挙が失敗しても他方を試します。列挙エラーやキャンセルがあれば終了コード1を返し、正常に列挙できて結果が0件の場合は失敗としません（終了コード0）。列挙結果の成功・失敗処理は、実機を使わない回帰テストでも確認します。異常終了時はビルドも失敗として停止します。
